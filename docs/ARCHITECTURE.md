# Architecture

How Smart Knife is put together, the rules the code follows, and the traps that cost real debugging time. The README
has the overview; this is the reference for working on the code.

## Layout

- `src/lib/registry.ts` — **source of truth**: `TOOLS` (slug, name, tagline, category, family, kind, keywords, optional `tabs`) and `SLUG_ALIASES`. Metadata only, no React, no side effects (imported by server and client).
- `src/lib/nav.ts` — the sidebar's layout (sections by task, Simple / Advanced groups, each Craft app on its own line); `src/components/shell/Sidebar.tsx` renders it. A new tool must be added there too (`tests/nav.test.mjs` fails otherwise).
- `src/tools/registry-client.tsx` — component key → lazy component map; unregistered tools render a placeholder. A suite (entry with `tabs`) renders one component per tab inside `src/components/SuiteShell.tsx` (accessible tabs, `?tab=<id>` sync).
- `src/tools/<ToolName>.tsx` — one tool per file, `"use client"` for browser tools.
- `src/components/ui.tsx` — shared primitives (Button, Panel, Field, Dropzone, Notice, Stat, OutputBlock…). Extend it; do not restyle per tool.
- `src/app/tools/[slug]/page.tsx` — generic: resolves the slug, 308-redirects retired slugs via `SLUG_ALIASES`, 404s unknown. Never add per-tool routes.
- `src/app/api/<name>/route.ts` — server endpoints (`account`, `admin`, `agent`, `cv`, `jobs`, `learn`, `mcp`, `pdf`, `sql`, `system`), `runtime = "nodejs"`; every mutating route reads its body through `readJsonBody` (JSON content type only, 415 otherwise) behind the Origin/Host guard.
- `src/lib/accounts/` — file-backed accounts in `$KNIFE_DATA_DIR` (default `~/.local/share/samurai-knife`, never in the repo). Provider keys never leave the server (routes return only `hasKey`/`keyHint`). Every mutating route goes through the Origin/Host guard in `http.ts`. Two modes (`KNIFE_AUTH_MODE`, `mode.ts`): `private` (default, owner-only) and `public` (registration with verified email, server-side sessions in `session.ts`, flows in `flows.ts`, roles in `authz.ts`, per-account data list in `data.ts`, mail in `src/lib/mail/`); pages `/login`, `/register`, `/verify`, `/forgot-password`, `/reset-password`, `/account`, `/account/admin` (UI in `src/components/account/`). Contract: `docs/ACCOUNTS.md`.
- `src/lib/mail/` — one outbound mail policy: address policy/canonical keys (`accounts/email-policy.ts`), bounded priority queue (`queue.ts`), global/domain/mailbox/collision budgets (`budgets.ts`) and suppression (`suppression.ts`). Budget and suppression snapshots are bounded, asynchronously persisted with HMAC'd identifiers under `$KNIFE_DATA_DIR/mail/`; all refusals/events use `security/events.ts`. Security mail carries an explicit high-priority kind. Contract and SMTP relay guidance: `docs/ACCOUNTS.md` and `docs/DEPLOY.md`.
- `src/lib/security/` — security events (`events.ts`, the one typed API; `events-core.mjs` the buffered daily-file writer shared with the preloads) and the abuse guard (`guard.mjs`: per-prefix and per-credential budgets, scanner scoring, escalating blocks; installed before Next by `scripts/abuse-guard.mjs`; `guard-bridge.ts` marks admins from `authenticate`), the admin alert digest (`alerts.ts`, started once by `src/instrumentation.ts`) and the admin view (`/api/admin/security`, `src/components/account/AdminSecurity.tsx`). Every refusal for abuse reasons records an event there; never write a second log. Docs: `docs/ACCOUNTS.md` "Abuse guard", "Security events".
- `src/lib/net/` — the one outbound path for URLs a user can steer: `address-policy.ts` (pure: reserved ranges, CIDR deny list), `safe-fetch.ts` (resolve once, every address checked, connection pinned to a checked address, no redirects, deny list = `KNIFE_SSRF_DENY_CIDRS` + the machine's own addresses), `outbound.ts` (per-account policy: private mode open; public mode users public https only, admins public unless `privateNetwork`; per-account outbound budget). Provider chat/Test/Responses (`src/lib/accounts/provider.ts`) and job/company pages (`src/lib/cv/jobs/fetch.ts`) use it; never call `fetch()` on a user-supplied URL. Docs: `docs/ACCOUNTS.md` "Outbound requests".
- `src/lib/agent-client/` + `src/components/agent/` — the chat widget, mounted once in `src/app/layout.tsx`. The loop runs in the browser: UI tools (`list_tools`, `open_tool`, `page_snapshot`, `fill_field`, `click`, `read_text`, `wait`, `upload_file`) act on the live DOM via `dom-bridge.ts`; `knife_*` tools run server-side via `/api/agent/tool`; `/api/agent/chat` proxies one provider round with the stored key.
- `src/lib/cv/` + `src/tools/cv/` — CV studio suite (bilingual CV profile, job offers, per-job versions, application tracker); contract and rules in `docs/CV-STUDIO.md`. Data is per account in `$KNIFE_DATA_DIR/cv/`, never in the repo.
- `src/lib/mcp/` — `POST /api/mcp`, stateless Streamable HTTP, same deterministic `knife_*` tools as the widget (`tools.ts` + `tools-sql.ts` + `tools-nosql.ts`, built with `define.ts`). Every tool declares `scope: "pure" | "account" | "admin"`; `toolsFor(ctx)` filters lists and calls by role on both surfaces. MCP authenticates per account with username + MCP key (`src/lib/accounts/mcp-keys.ts`, keys on `/account`); private mode without a key keeps the default account. Contract: `docs/MCP.md`.
- Agents outside the app (OpenClaw, Claude, Cursor…) steer it over MCP: data through the `knife_*` tools (open pages refresh by themselves: CV studio polls every 2 s and toasts the change with Undo), the page through the MCP-only `knife_ui_state` / `knife_ui_show` / `knife_ui_call` (`src/lib/mcp/tools-ui.ts`, `src/lib/ui-bridge/`, `src/components/shell/UiBridge.tsx`: tabs report presence (with the page's live tools) to `POST /api/ui/presence`, a visible tab polls `GET /api/ui/poll` every 1.5 s; `showPath` only builds `/tools/<registry slug>?tab=&job|variant|focus|doc`; `knife_ui_call` runs one `doc_live_*` / `craft_*` tool in the visible tab through `src/lib/agent-client/external-call.ts`, behind the same approval policy, and the tab answers `POST /api/ui/call`; a file a tool made reaches the agent only by `craft_file_save` into the account's Craft files and the MCP-only `knife_craft_files` / `knife_craft_file_read`, `src/lib/mcp/tools-craft-files.ts`). Contract: `docs/MCP.md`.
- Server work: all Python-lane calls go through `src/lib/work-queue.ts` (lanes `light` = sql, `heavy` = pdf; env `KNIFE_PY_LIGHT` 4, `KNIFE_PY_HEAVY` 1, `KNIFE_PY_HEAVY_DEPTH`, `KNIFE_JOB_TTL_SEC`; bounded depth -> 503 + Retry-After; client abort kills the process group). `POST /api/pdf?async=1` returns 202 `{jobId}`; `GET /api/jobs/<id>`, `/file`, `DELETE`; `GET /api/system/queue` for stats (lanes, jobs, uploads in flight). Public-mode load budgets, each one module: `src/lib/python-admission.ts` (who gets how much of a lane: administrators privileged = the lane's reserved places + started first + no rate; ordinary accounts heavy 1 / light 3 jobs, new accounts (< `KNIFE_PY_NEW_ACCOUNT_HOURS` 24) light 2; jobs per 10 min heavy 30 / light 120, new 10 / 40; refusals are `QueueFullError` scope `owner`/`rate` = 429, `lane` = 503), `src/lib/upload-budget.ts` (a slot per streamed upload taken before the first body byte, released in `finally`: public 2 per account / 6 server-wide with one kept for admins / 512 MB in flight, private 8 / 16 / 4096 MB; `KNIFE_UPLOAD_IDLE_SEC` 30 without a byte = 408; refusals 429/503 + Retry-After), `src/lib/storage/disk-floor.ts` (free-space floor = max of `KNIFE_DISK_FLOOR_GB` 10 and `KNIFE_DISK_FLOOR_PERCENT` 10, statfs cached 10 s; refuses non-admin data writes (`StorageFullError` 507 `storage_full`, from `assertCanStore`) and every upload into the scratch dir (503)). `KNIFE_PDF_UPLOAD_MAX_MB` defaults to 100 in public mode.
- Untrusted CPU work on the server (a user-supplied regex, a parser over an uploaded file) runs in the isolate pool `src/lib/isolate/` (`server.ts` `runIsolated(task, payload)`; tasks in `tasks.ts`, worker entry `worker.ts` started with `new Worker(new URL("./worker.ts", import.meta.url))`, which Turbopack bundles as its own chunk; `pool.ts` = queue, per-account share, timeout that terminates the worker, heap cap). Users: `knife_validate_json_schema` (Ajv `pattern`s, 2 s), `knife_generate_regex` (2 s), office text (`src/lib/office/extract.ts`, 10 s; `knife_doc_read` and the version preview). Env `KNIFE_ISOLATE_WORKERS` 2, `KNIFE_ISOLATE_QUEUE` 16, `KNIFE_ISOLATE_PER_ACCOUNT` 4, `KNIFE_ISOLATE_HEAP_MB` 256; full -> QueueFullError (`queueFullOrNull`: 503/429 + Retry-After); stats in `GET /api/system/queue` (`isolate`).
- Browser work: heavy tools offload to Web Workers through `src/lib/workers/` (typed pool: queue, cancel = terminate + lazy respawn, timeout, crash recovery). Small inputs (<~100k chars) stay inline so behaviour is identical; larger ones show `WorkStatus` (role=status) with a Cancel button. sql-lab Run keeps SQLite (sql.js) in a worker with snapshot restore on cancel.
- Assistant runtime: one typed store (`runtime-store.ts`: idle -> preparing -> thinking <-> tool <-> awaiting_approval|awaiting_user, summarising, stopping) with the message queue (Enter while busy queues; chips can cancel/edit/send-now = steer at the next round boundary; Stop pauses the queue) and a per-account run lock across tabs. Telemetry: `src/lib/usage.ts` + `usage-ledger.ts` (per-account counters in the data dir, `GET /api/account/usage`), per-turn footer = a `notice` with `level:"usage"` (never sent to the model).
- Databases (no live connections, by design): `src/lib/sql/types.ts` is the SQL contract (QuerySpec zod schema, dialects, actions); `POST /api/sql` -> `server/py/scripts/sql_tool.py` + `sqlkit/` (sqlglot: format, transpile, validate, schema, compile, check); `src/lib/nosql/` is pure TS (Mongo, Chroma, Redis; docs-derived rule tables); `src/tools/db/` holds the `sql-lab` tabs (the NoSQL lab page was removed in the 2026-10-25 audit; its `knife_mongo_*` / `knife_chroma_*` / `knife_redis_*` MCP tools stay); sql.js (SQLite WASM) runs in the browser, assets copied to `public/sql/` by `scripts/prepare-sql-assets.mjs`.
- `server/py/scripts/*.py` — Python lane; venv lives **outside** the repo at `../samurai-knife-py/venv` (override with `KNIFE_PYTHON`). `src/lib/python.ts` owns execution and per-job binds; public mode defaults to a probed bubblewrap sandbox (`KNIFE_PY_SANDBOX=auto`), no network and no data/key visibility. `off` is explicit and warns in public mode; see `docs/DEPLOY.md`.
- `scripts/serve.mjs` — `npm run dev|start` binds `KNIFE_HOST` (default `127.0.0.1`) : `KNIFE_PORT` (default 3210) from gitignored `.env.local` (see `.env.example`).
- `deploy/` — production install as a dedicated `knife` user under systemd: `install.sh` (root installer, idempotent), `bin/knife-update` (release builder/activator run as `knife-deploy` on a timer), `bin/knife-admin` (accounts/storage/email-lists as `knife`), `systemd/` units, the polkit restart rule, the root sidecar helper and optional firewall pieces. Contract: `docs/DEPLOY.md` "Install script"; invariants pinned by `tests/deploy_install.test.mjs`.
- `legal/` + `src/lib/legal/` + `src/app/{terms,privacy}/` + `src/app/api/legal/` — Terms of Service and privacy notice (Polish binding, English): defaults with `{{placeholders}}` in `legal/`, the instance's `legal.json` and page overrides in `$KNIFE_LEGAL_DIR` (never in git), sign-up records the accepted version (`termsAcceptedAt`/`termsVersion`); editions of the defaults in `legal/versions.json` + `legal/editions/<n>/`, every version an instance showed in `$KNIFE_DATA_DIR/legal-history/` (`?version=` / `?edition=` read earlier ones; effective date never before first shown). Contract and the legal research: `docs/LEGAL.md`.
- `src/lib/i18n/` + `src/components/LanguageSwitcher.tsx` + `src/app/api/locale/` + `scripts/i18n-extract.mjs` — interface languages (English, Polish): English text is the key, `src/lib/i18n/pl.json` the Polish catalogue (plurals one/few/many), `useT()` in components, `getT()` in server components, `msg()`/`msgf()` for module-level texts and server messages (translated back by template in the browser), the choice in the `knife_lang` cookie and on the account; the SQL course overlay is `src/lib/learn/sql/lessons.pl.json`, emails take a `locale`. Contract: `docs/I18N.md`.
- `src/lib/logs/` + `src/app/api/admin/logs/` + `src/app/account/admin/logs/` — log files: one root `$KNIFE_LOG_DIR` (default `<repo>/logs`, gitignored; systemd install `<app-root>/logs`), one folder per source (`app/` = the server's stdout/stderr teed by `scripts/serve.mjs`, `sidecars/<id>/` = sidecar ops, `update/` = `knife-update`), daily UTC files with a size cap (`.1`..`.9` parts), past days gzipped, secrets redacted, retention = legal.json `logRetentionDays` (default 30) at startup and hourly. `core.mjs` is plain `.mjs` (serve.mjs uses it); the admin viewer is read-only with allow-listed sources/names, no symlinks, bounded tails; security events stay in the data dir and are shown there too. Contract: `docs/DEPLOY.md` "Log files".
- `tests/` — Python Playwright e2e suites, `mock_provider.mjs`, `tests/functional/*_e2e.py` per tool group. How to run: `docs/TESTING.md`.
- `src/lib/services/` + `src/app/api/services/` + `scripts/services.ts` — optional compose sidecars (lazy start, idle stop, autostart: start at app boot, back within a minute, admin Stop holds; docs/SIDECARS.md); docker CLI remains the default backend, while public deployments can use the fixed-verb root helper (`KNIFE_SIDECAR_BACKEND=helper`, `KNIFE_SIDECAR_HELPER_SOCKET`) so the app user is not in the docker group. With the helper, `src/lib/services/sync-check.ts` re-stages each installed bundle after every server start and shows admins "Sync needed" (Sidecar services page, `/account/admin`) when root's copy lags the release; `sudo knife-sidecar check <id>` prints what differs, only the owner runs `sync`. Definitions include required capability drop/add, no-new-privileges and pids limits. Contract and deployment: `docs/SIDECARS.md` and `docs/DEPLOY.md`.
- `src/lib/services/sites.ts` + `src/lib/craft/` + `src/app/api/craft/` + `src/tools/craft/` + `scripts/craft-proxy.mjs` — ArtCraft suite `artcraft` (one tab per app: PhotoCraft, VectorCraft, FilmCraft, LightCraft, EffectCraft, DesignCraft, PdfCraft, FigCraft, WordCraft, SoundCraft, DeckCraft, CADCraft, GridCraft; static WebAssembly builds, MIT OR Apache-2.0) on the `craft` sidecar: a read-only, capability-free nginx serving the pinned release zips (`ARTCRAFT_APPS` in definitions.ts: version + sha256, downloaded and unpacked into `$KNIFE_DATA_DIR/services/craft/assets/`, never in git) on its OWN origin (private: its port on KNIFE_HOST; public: `KNIFE_CRAFT_PUBLIC_URL`, proxied by the app with a ticket cookie). Each tab is an iframe with exactly the README's sandbox and `allow` (`SidecarSite.sandbox` / `.allow`). Contract: `docs/SIDECARS.md` "ArtCraft". Craft files: the bridge page `sidecars/craft/knife-bridge/` (served at `/knife-bridge/` from the content dir) turns the apps' Save/Open into the account's files (`src/lib/craft/files.ts`, `craft-files/<id>/`, `/api/craft/files`) and clears the craft origin's storage when another account used that browser; docs/SIDECARS.md "Craft files". The assistant drives the apps that have a browser agent API (VectorCraft, FilmCraft, EffectCraft) through the same bridge: `craft_*` tools in `src/lib/agent-client/craft-live-tools.ts` (group `craft_live`, page-only, offered only once the app answers), registry `src/lib/craft/live.ts`; docs/SIDECARS.md "The assistant inside an app".
- `src/lib/workflows/` + `src/app/api/workflows/` + `src/app/api/hooks/` + `src/app/api/hooks-test/` + `src/tools/workflows/` — n8n-style workflows (suite `workflows`): own clean-room engine (items, `={{ }}` expressions, depth-first executor, Wait/resume, sub-workflows, error workflows), core nodes, React Flow editor, credentials (sealed; OAuth2 with the user's own app). Every run is a worker process (`worker/main.ts`, Node's permission model, TypeScript run by type stripping) and user JavaScript runs in QuickJS-WASM. Contract: `docs/WORKFLOWS.md`; node inventory: `docs/research/n8n-nodes.md`.
- `src/lib/office/` + `src/app/api/office/` — office library (`$KNIFE_DATA_DIR/docs/<account>/`: documents, `folders.json`, kept versions, trash; `store.ts` + `folders.ts`; the office tab is a file browser, `src/tools/sidecars/OfficeTool.tsx` + `OfficeEditor.tsx` + `OfficeVersions.tsx`), blank OOXML/ODF in TS, text extraction, Euro-Office editor config (JWT-signed server-side). `GET /api/office/ds/file` and `POST /api/office/ds/callback` are called by the container and are the **only routes without the Origin/Host guard**: they authenticate by JWT (capability `t` + the server's Bearer token), every token kind owned by `src/lib/office/ds-auth.ts` (`authorizeDsRequest`). `knife_doc_*` tools in `src/lib/mcp/tools-docs.ts` (group `docs`).
- Live editing of the OPEN document: editor plugin `sidecars/office/plugins/knife-bridge/` (system plugin, mounted into the sidecar by the definition's `assets`, `src/lib/services/assets.ts`), browser bridge `src/lib/office/live-bridge.ts` + protocol `live-protocol.ts` (hello/welcome over postMessage, then a private MessagePort; per-session token in the signed editor config), assistant tools `doc_live_*` in `src/lib/agent-client/office-live-tools.ts` (group `office_live`, page-only, offered only while connected and per editor type). Contract: `docs/SIDECARS.md` "Live editing plugin".
- `src/lib/learn/` + `src/app/api/learn/` + `src/tools/learn/` — Database course (launcher category Learn, suite `db-course`, one tab per course; first: SQL & PostGIS, 46 lessons as data in `src/lib/learn/sql/lessons.ts`). Contract: `docs/LEARN.md`.

## Adding a tool

1. Add an entry to `TOOLS` in `src/lib/registry.ts`; keep `category` broad, pick the closest `family`. Prefer a new tab in an existing suite when the tool fits one.
2. Write the component in `src/tools/`, register it in `registry-client.tsx`.
3. Add the tool to ONE section of `src/lib/nav.ts` (see "Sidebar"); a new tab needs nothing there.
4. `npx tsc --noEmit && npm run lint`; `tests/nav.test.mjs` fails until the tool is in the menu exactly once.

Launcher, search, categories, counts, metadata and static params all read the registry; the sidebar layout is the one
hand-made list.

## Sidebar

`src/lib/nav.ts` + `src/components/shell/Sidebar.tsx`, built on NN/g's guidance for left-side vertical navigation and
menus (nngroup.com/articles/vertical-nav, /articles/menu-design): visible, left-aligned, key word first, the current
location always shown, submenus marked by a chevron and opened by click.

- One entry per destination: every tool exactly once (no tab entries, no "Recent" copy of entries). A suite's tabs are
  local navigation, nested under the tool you are in. Only the Craft apps are listed per app, because that suite hides
  its tabs on the page.
- Sections are named by what people work on ("Documents and PDF", "Images", "Craft apps", "Data and databases", "Text",
  "Web and code", "Career", "Automation", "Learning"); no "simple/advanced" levels. Within a section the big workspaces
  come first, then the smaller tools by how often they are needed. Setup pages sit in the footer.
- The section holding the current page stays open; other sections fold and remember it per browser. A filter at the top
  matches tools and tab names. Breadcrumbs use the section label (`navSectionOf`).

## Rules

- **Browser first.** If a tool can run client-side it does; files are not uploaded. Use the Python lane only when the format needs a real library (PDF, DOCX, OCR, video).
- **Python contract.** Scripts read `request.json`, write `response.json` (`{"ok":bool,"data":…}` or `{"ok":true,"file":…,"mime":…}` for an artifact in `out_dir`; message in `error`). No daemon, port or state; per-request scratch dirs removed in `finally`.
- **Slugs are permanent.** Never rename or delete one. To fold a tool into a suite: remove its `TOOLS` entry, add it as a tab (`tabs: [{ id, label, component }]`, `component` = old slug), and add `"<old-slug>": { slug: "<suite>", tab: "<tab-id>" }` to `SLUG_ALIASES`. Never remove an alias.
- Accounts depend on `KNIFE_AUTH_MODE` (docs/ACCOUNTS.md). Private (default): accounts are added only with `npm run accounts`, never over HTTP; access control is the loopback/Tailscale bind and the passwordless default account is the implicit identity; the public-only routes and pages answer 404. Public: self-registration with a verified email, every request needs a session, nothing ever falls back to the default account (`resolveAccount` returns null, MCP included), and shared or server-wide operations go through `requireAdmin` (`src/lib/accounts/authz.ts`). MCP needs username + an MCP key in public mode (`src/lib/accounts/mcp-keys.ts`, docs/MCP.md). Every `defineTool` declares `scope` (`pure`/`account`/`admin`); anything that reaches the server owner's own resources (host `gh` login, host disk) is `admin`, and lists/calls go through `toolsFor(ctx)` on both the widget route and MCP. Per-account browser storage keys are listed in `src/lib/client-account.ts` (cleared on logout); a new one goes there. Child processes get `childEnv()` (`src/lib/child-env.ts`), never `process.env`. Responses to register/resend/forgot never reveal whether a username or address exists. Never bind `0.0.0.0` in either mode (public runs behind a reverse proxy on this machine).
- Every per-account path comes from `accountScope(id)` (`src/lib/storage/scope.ts`: validated id, `safeJoin` per segment, symlinked dirs refused); `src/lib/accounts/data.ts` lists them for account deletion. A new per-account store gets its path there, never by joining an id itself. User-content writes go through `writeAccountFile` (`src/lib/storage/quota.ts`): the quota is checked BEFORE writing (507 `storage_quota_exceeded`, readable message; admins unlimited); bookkeeping writes pass `enforce:false` but still go through it so the cached usage stays exact.
- The widget must never appear in its own page snapshot.
- Server tools are gated by their declared effect (`src/lib/mcp/define.ts` `effect`/`urlArgs`/`destructiveWhen`/`untrustedOutput`/`publishes`) in `src/lib/agent-client/server-tool-policy.ts`, never by name. Third-party text handed to a model goes through `wrapUntrusted` (`src/lib/security/untrusted.ts`); once it entered a conversation the taint is sticky until Clear (server flag + `x-knife-untrusted` header), and an outbound call to a host the user did not type (outside pasted/quoted text) or a publishing write asks in every trust mode but None. External MCP clients get annotations and instructions and must gate themselves (docs/MCP.md).
- Outbound requests go through `src/lib/net/safe-fetch.ts` and the central `src/lib/net/outbound.ts` admission gate (never bare `fetch` for user-controlled destinations). In public mode, non-admins are limited per account (`rate-limit.ts` LIMITS) and by server-wide purpose and destination-host sliding windows (`KNIFE_OUTBOUND_BUDGETS`, `src/lib/net/budgets.ts`); the shared windows are fair-share (past `max` only accounts under their share are admitted, hard ceiling 2 x max), the host window covers user-chosen hosts only (pages, audited sites, admin-approved provider URLs; never allow-listed providers, GitHub or PageSpeed, so a few bot accounts cannot cut everyone off), admins are never budgeted; a refusal is an `outbound_budget` security event. Provider URLs are restricted to known LLM hosts or an admin-approved per-account URL (`KNIFE_PROVIDER_HOSTS`). Site audits and page reads of non-admins go only to the connected production origin once verified through GitHub (homepage or Pages host) or admin-approved (`src/lib/site/ownership.ts`). Server-held PageSpeed/host credentials are admin-only; non-admins spend only their own connected credentials. Upstream response bodies from arbitrary hosts are not echoed to non-admins.
- Request bodies: JSON through `readJsonBody` (Content-Length and streamed byte cap, 413 with a message); multipart through `receiveMultipart` (`src/lib/multipart-upload.ts`: streamed to disk, request/file/count caps); never `request.formData()`/`request.text()` on an unbounded body.
- Child processes get an explicit environment (`childEnv` in `src/lib/python.ts`), never `{...process.env}`; Python scripts start through `server/py/scripts/run_limited.py` (RLIMIT_AS/CPU/FSIZE per lane).
- Provider secrets are sealed in `accounts.json` (`src/lib/accounts/secret-box.ts`, key file `provider-keys.key`); code that reads the file raw (tests, scripts) must go through the store or `npm run accounts -- provider-json <id>`.
- Versions: `VERSION` = MAJOR.MINOR.PATCH.BUILD, bumped in every commit by `scripts/git-hooks/pre-commit` (`npm run hooks` once per clone; `KNIFE_NO_BUMP=1` skips; VERSION-only commits are not bumped); package.json `version` = the first three parts; a release is the tag `v<VERSION>` (docs/DEPLOY.md "Releases").
- Public mode gates every page but `/` and the auth pages: the root layout only picks the frame (`isGuest` -> `PublicShell`, no sidebar/assistant/UI bridge; else `AppShell`), the gate itself is `requireSignIn(path)` (`src/lib/accounts/viewer.ts`) called by each tool/account page, because layouts are not re-rendered on client navigation. A new page that needs an account must call it too. Private mode never gates. Scratch-server tests see only tracked files: `git add` a new module before running them.
- Tool drafts (`src/components/WorkspaceDraft.tsx`) wrap every browser tool: a tool that loads server data or handles secrets goes in `NO_DRAFT` (`src/tools/registry-client.tsx`), the wrapper never re-renders the tool (memoized element: a re-render resets controlled fields typed before hydration) and never shows its own `role=status` line (automation reads the first `main [role=status]`). UI tests must wait for hydration before typing (React props on a `main` control), not a fixed delay.
- Per-account files are sealed at rest by `writeAccountFile` (`src/lib/storage/sealed.ts`, key `storage.key` or `KNIFE_STORAGE_KEY_FILE`): read them only with `readAccountFile` / `readAccountText` (a raw `readFileSync` gets ciphertext; copying one into a new file with `writeAccountFile` would seal it twice), and hand the Python lane a plaintext copy in its own scratch dir, never a data-dir path.
- No user-supplied regex or parser on the server's main thread: Node has no regex timeout, so one backtracking pattern (`^(a+)+$`) or a crafted file stops the event loop for every user. Run it through the isolate pool (`runIsolated`, `src/lib/isolate/server.ts`; add a task in `tasks.ts`), cap its input size, and bound what it builds while it builds (`TextBudget` in `src/lib/office/text.ts`), not after. Constant patterns over user text are fine when they have no nested or overlapping quantifiers.
- **Legal texts follow the features.** A feature that stores new personal data, sets a new cookie or browser storage entry, or sends data to a new recipient changes the privacy notice (and the Terms for a new service or rule) in the same release, both languages, as a new edition: `legal/versions.json` (editions + `covers`), `legal/editions/<n>/`, the texts' change history. `tests/legal.test.mjs` fails on a new cookie constant or `StorageArea` outside `covers`, and on a text change without its digest. Steps: `docs/LEGAL.md` "Changing the texts".
- **Workspace pages** (registry `workspace`, Craft apps and Workflows): ToolShell marks `<main data-workspace>` in the server render, so on desktop the page has no tool heading or suite tabs and fills the window below the top bar from the first paint (globals.css); never switch that layout on from a client effect, the regular page would show first. `hideSidebar` (Workflows) hides the tool sidebar the same way; the toggle only peeks, the stored preference stays.
- **Code fields** use `src/components/CodeEditor.tsx` (CodeMirror): the editable content carries `data-agent-code`, so the assistant's snapshot lists it as a textarea and `fill_field` replaces its text (events `knife:code-read` / `knife:code-fill`, dom-bridge.ts). A plain textarea needs nothing.
- **Full screen is in the page**: `FullscreenButton` / `usePageFullscreen` (`src/components/ui.tsx`) make an element cover the page (`data-page-fullscreen`, globals.css; `data-page-fill` takes the rest of the height), never the browser Fullscreen API: that shows the element alone and loses Smart Knife's drawers and dialogs (a Craft app's file chooser). Embedded third-party apps are never linked bare: "Open in new tab" opens our page (`?full=1`), or Save/Open lose the account.
- **Every visible text goes through the translator** (`t` / `tn` / `msg` / `msgf`, docs/I18N.md): one key per full sentence (never split a sentence around a value or a link, never build a plural with `"s"`), and `node scripts/i18n-extract.mjs --write` + a Polish translation in `src/lib/i18n/pl.json` in the same commit (`tests/i18n.test.mjs` fails on a missing, stale or mismatched key). Slugs, ids, code, SQL and the deterministic `knife_*` tool output stay English.
- No new dependencies without a reason in the commit message; prefer Web APIs.
- Type everything, no `any`. Typecheck and lint clean before reporting done.
- Tests use the mock provider by default. Never point tests at a shared model server.

## Gotchas
- Registration fields are browser-owned, named inputs read through `FormData` on submit; never disable signup from change-event field state. Password managers may fill without events, and a consent rerender must not erase those values (`tests/functional/signup_autofill_e2e.py`).

- Workflows: code the worker imports (`src/lib/workflows/{types,catalog,engine,nodes,sandbox,worker}` and what they import) runs under Node's type stripping: erasable TypeScript only, directory imports as `…/index`. Start the worker with `spawn` + an IPC slot, never `fork(path)` (Next traces it into the bundle). Webhook routes are the only workflow routes without a session: never echo a caller's cookie into a run, never let a run set one.
- Agent e2e helpers that wait for "my prompt got its reply" must not match on message count or on "the last user message equals my text": the stored transcript is capped (`MAX_STORED_MESSAGES`), survives reloads, and suites repeat prompts, so the previous run's reply reads as the new one. `agent_trust_modes_e2e.py` prefixes every prompt with a unique `run N` line (the mock reads `CALL:` anywhere); `tests/conversation_support.py` waits on the server-side conversation instead. The Stop button (= "running") appears before the user message reaches the server transcript (one GET + PUT later): never read `/api/agent/conversation` right after `wait_running`, poll for the message first.
- The conversation's `untrusted` taint is owned by `/api/agent/chat` via `conversation-store.ts`; never write it from the browser or a PUT. Every provider, an OpenClaw gateway included, is called through `/chat/completions` with the (slimmed) history; there is no server-side continuation (removed 2026-10-25; old conversation files and account configs with its fields are read with those fields stripped).

- HTTP Tailscale origin is not a secure context: no `crypto.subtle`/`randomUUID`; use `@noble/hashes` and `src/lib/random-uuid.ts`.
- `crypto` hashing needs the whole buffer in memory, so browser file hashing/compression is capped at 512 MB on purpose.
- `suppressHydrationWarning` sits only on root `<body>` (extensions inject `cz-shortcut-listen`); never use it to hide app subtree mismatches.
- Firefox restores a `<button>`'s dynamic `disabled` state across reloads before React hydrates (attribute mismatch on any button disabled on the server and enabled after hydration, e.g. favorites waiting for localStorage). Every `<button>` carries `autoComplete="off"` (typed in `src/types/react-button.d.ts`); `tests/hydration_e2e.py` has a Firefox reload pass (`python3 -m playwright install firefox`).
- Hydration mismatches come from locale/timezone-dependent render output: never call bare `n.toLocaleString()` / `Intl.*(undefined, …)` in anything SSR renders; use `formatInt` (`src/lib/format.ts`) or a pinned locale. Guard: `python3 tests/hydration_e2e.py <url>` (pl/de/ja locales, every tool and tab); a headless run in the server's own locale never reproduces these.
- Every host/IP the app is opened from must be in `KNIFE_HOST` or `KNIFE_ALLOWED_HOSTS` (`.env.local`, read by `src/lib/hosts.ts` for `allowedDevOrigins` and the Host/Origin guard), or dev HTML renders but never hydrates and API calls get 403. Never hardcode hosts in the repo.
- Next 16 deprecates middleware; don't add a proxy file unless request-level routing is truly needed.
- Turbopack panics on a `node_modules` symlink pointing outside the project: in a worktree use `cp -al <main-checkout>/node_modules node_modules`, then `npx next typegen` once.
- tsc errors under `.next/types` for deleted routes: run `npx next typegen`.
- npm ≥10 blocks postinstall scripts; after a fresh install run `npm install-scripts approve unrs-resolver`.
- Lazy tool/tab chunks show a `role=status` "Loading tool…" line; UI automation must wait for it (`waitForToolPanel` in `dom-bridge.ts`).
- Single-key shortcuts (`a`, `b`, `g h`, `[`, `]`, `/`, `?`) are global: they must skip typing targets, and any overlay with a text input must `autoFocus` it so fast typing never fires shortcuts.
- Shell chrome (sidebar, top bar, palette) stays outside `<main>` so agent snapshots never see it; the widget stays in the root layout so agent navigation never reloads it.
- The agent never fabricates the user's real files/data: open the tool, then `wait_for_user` (control id pulses); trust modes All/Most/Risky/None gate acting calls (default Risky; a stored choice wins), destructive ones are confirmed one by one and never covered by "allow rest of run". Destructive = Delete/Clear/Reset-style buttons, emptying or overwriting the user's textarea, a suite tab switch, same-tab link or page change while the user's input is there, Sample/Restore/Use-output-as-input/Apply-to buttons over it, and `upload_file` over a file the user chose (a Dropzone empties its list, so the pick is remembered in `userPickedFile` until the assistant replaces it; leaving a page for the next tool in a chain is deliberately NOT prompted for those picks). In the open office document, `doc_live_delete`, `doc_live_replace` (every match), `doc_live_cells_write {overwrite:true}`, `doc_live_delete_slide`, `doc_live_slide_text` and `doc_live_header_footer` are destructive; other `doc_live_*` edits are acting calls, reads never ask. In an open Craft app, `craft_execute`/`craft_request`/`craft_import`/`craft_file_save` act (`craft_file_save {replace:true}` is destructive), and an id or method naming delete/remove/clear/reset/revert/discard/close/quit/exit (also inside `ui.menu.invoke`) is destructive; every Craft answer taints the conversation like a page read. Only user-authored input counts (`userValues`/`userFileLists`/`userPickedFile` in `dom-bridge.ts`: what the assistant itself wrote is free to discard); blank checks must ignore zero-width characters.
- SQL: compile/transpile output is only trusted after `check`/`validate`; transpile reports (`issues`) what does not convert exactly, including functions SQLite lacks (`PRAGMA function_list` is the oracle). MariaDB compiles as the sqlglot `mysql` dialect. Engine/NoSQL tests need no database server; extend the transpile corpus together with an executable sqlite case.
- Tool definitions are re-sent on every model round, so size matters: the database tools (about 22k characters) are NOT in the request on ordinary pages. `tool-groups.ts`: preloaded on `/tools/sql-lab` and `/tools/nosql-lab`, kept once a conversation used them, otherwise the model calls `load_tools {group}`. Adding a tool group = a prefix entry in `TOOL_GROUPS`. Check cost with the usage footer (mock provider usage = request chars / 4).
- `wait_for` (not `wait`) is for slow async page work (OCR): conditions busy_done / new_file / text / regex / change / idle, up to 120 s, abortable. Long operations must expose progress as `role=status` text.
- `navigator.locks` is undefined on the plain-HTTP production origin: the run lock falls back to a localStorage lease. The mock provider's `/__stats` peak is cumulative (DELETE it per scenario). Workers must not be created at page load or during SSR/hydration (Playwright `networkidle` never settles while a worker script is in flight).
- Tool chaining: `artifacts.ts` wraps `URL.createObjectURL` + `HTMLAnchorElement.prototype.click` to capture every tool's download (`<a download>`, attached or detached) as `f1…`; the model passes `upload_file {from_file}` / `read_text f1`, never bytes (models corrupt base64). No per-tool wiring: a new tool that downloads via a blob anchor chains for free.
- `tests/mock_provider.mjs` reads one `CALL:name:{json}` per line (greedy regex): put multiple calls on separate lines.
- PDF text extraction is text-layer only; scanned PDFs need OCR. The npm package name is lowercase (`samurai-knife`) though the folder is not.
- Real-model runs: `python3 tests/agent_coverage_e2e.py` with no URL starts its own isolated server (throwaway worktree of the current tree + temp data dir + free port) and removes all of it on exit; with a URL it only targets that server. Prefix `KNIFE_REAL_ACCOUNT=openclaw`. Run `--list` first (every registry target must be in CASES or SKIPS). `--in-place` skips the worktree (only when nothing else runs from this checkout).
- Manual browser walkthroughs and Playwright suites must not share a server: several suites refuse a used data dir (cv_studio: "needs a fresh KNIFE_DATA_DIR"). Use one scratch server for clicking around, restart another with a fresh data dir per suite.
- Playwright waits that race a toast: a toast can contain the very text you assert (the CV replace toast says "Jan Testowy -> Zmieniony"), so wait on the field itself before reading the API.
- Cancel buttons on worker jobs exist only while the job runs and `WorkStatus` shows them after 300 ms; Sentences/Punctuation on 14 MB finish in ~0.2 s while the native textarea layout freezes the page ~3.5 s, so the window is 100-200 ms. Cancel tests delay `Worker.prototype.postMessage` (`SLOW_WORKER` in `offload_text_e2e.py`) instead of hoping for a long job. CDP CPU throttling does not slow workers.
- `tests/scratch_server.py` builds its worktree from `git stash create`: tracked edits only. A **new untracked** Python module the worker imports (`from pdf_ocr import ...`) is missing there, so every request dies with `ModuleNotFoundError`. Copy it in after `server.start()` (`shutil.copytree(ROOT / "server/py", server.cwd / "server/py", dirs_exist_ok=True)`, as `pdf_ocr_api_e2e.py` and `pdf_searchable_e2e.py` do), or commit the file first.
- Playwright `get_by_label("X", exact=True)` reads the *wrapping* `<label>`'s inner text. `Field` (src/components/ui.tsx) wraps the control in a `<label>` together with the `<span class="sk-label">`, so for a `<select>` the label text also contains every `<option>` row and an exact match never lands (count 0). Use `get_by_role("combobox", name="X", exact=True)` for selects; `get_by_label` is fine for checkboxes/text inputs whose label has no option children.
- Sidecars: a container reaches the host's Tailscale/LAN address but never its loopback, so sidecar e2e servers bind the Tailscale IP (`ScratchServer(host=...)`) and set `KNIFE_SIDECAR_PREFIX` so they never take over a running `samurai-knife-<id>` compose project. Never touch containers outside a `samurai-knife-*`/test project. Euro-Office writes its font cache into the container filesystem: `GENERATE_FONTS=false` + the definition's `prepare` step (once per container id) keeps cold starts at ~12 s; without the cache the editor never finishes loading although `/healthcheck` says true.
- Office editor proxy (`KNIFE_OFFICE_PUBLIC_URL`, `scripts/office-proxy.mjs`): the editor must stay on its OWN origin (never a path on the app's origin: a document/editor bug would act as the signed-in user); app and office names must share a registrable domain (SameSite=Strict ticket cookie). A new editor path the proxy refuses shows as `[office-proxy] refused <path>` in the server log; extend the allow-list only for editor-facing routes and rerun `tests/office_proxy_e2e.py`.
- Craft agent APIs: FilmCraft and EffectCraft define `window.<app>` before the app runs and reject every call ("… is not running yet"), VectorCraft only after start: readiness = `inspect()` answers, never "the object exists". Screenshots: FilmCraft/VectorCraft answer `pngBase64` (VectorCraft only with `{data:true}`), EffectCraft `png`. Imports differ per app (`importFiles`, `openFile(name, bytes)`, `addFile(File)`); the bridge's `import` picks the one there.
- Office live plugin: nginx serves `sdkjs-plugins` as `immutable` for a year, so the plugin folder carries a content hash (`knife-bridge-<sha>`), re-synced on every `ensure`; never serve it under a fixed name. Plugin command bodies are stringified by `callCommand` and run inside the editor: no closures, only `Api` and `Asc.scope.args`; one command at a time (single callback slot). `Api.Save()` from a plugin does not save in 9.3.5: force-save via the command service (`POST /api/office/docs/<id> {action:"forcesave"}`; `unchanged` right after an edit = not sent yet, retry). `ApiDocument.GetStyle(name)` returns the DEFAULT style for an unknown name: compare `GetName()`. `Api.CreateShape` text is white by default (shape style): set `tx1`. Playwright: keyboard focus inside the editor iframe swallows Ctrl+J; click page chrome first. Excel's built-in formats ("0.00" = id 2) are saved as `numFmtId`, not as a `formatCode`: assert on either.
- `tests/scratch_server.py` `start(overlay=[...])` copies untracked paths (new modules, a new plugin) into the stash-based worktree before the server starts.
- Background requests in the shell (presence, polls) must READ their response body, including on 401: an unread body stays in flight and the page's network never goes idle (Playwright `networkidle`, the assistant's idle waits). Never hold a long-lived connection (SSE) per tab: Chrome counts one opened before `load` as loading, `networkidle` never fires, and HTTP/1.1 allows 6 connections per site.
- State kept on `globalThis` survives HMR in a long-running dev server: when its shape changes, version the key or validate the shape (`src/lib/ui-bridge/store.ts`), or the live app keeps the old object and crashes while scratch-server tests (fresh process) pass.
- Database course: never let learner SQL end the runner's transaction (BEGIN/COMMIT/ROLLBACK are refused by `classifyStatement`; savepoints are fine) and run every learner query on a fresh connection; the role's privileges are the boundary, the statement policy only explains. Any change to `src/lib/learn/sql/seed.ts` needs a `SEED_VERSION` bump, or existing installs keep the old data. Lesson ids are progress keys: never rename one. `tests/learn_db_e2e.py` must pass after lesson edits (every reference solution against the real database). Learner statements run as streaming queries (`streamQuery` in `db.ts`, rows into a `RowCollector`), never `client.query` with an accumulated result: node-postgres would buffer every row and every message whole. The learner client's socket goes through `WireGuard` (`limits.ts`), so it must stay plain TCP (`ssl: false`).
- Startup checks (`scripts/deploy-config.mjs`, run by `serve.mjs`): public mode needs `KNIFE_PUBLIC_URL` (https) and `KNIFE_TRUSTED_PROXIES`; an empty `KNIFE_AUTH_MODE` with `KNIFE_PUBLIC_URL` is refused (a private install that uses the URL for the GitHub App says `private` explicitly); private mode never binds or allows a public host. `mode.ts` and `guard.mjs` `guardMode` share the empty-mode rule. Public-mode scratch servers get loopback defaults for both (`tests/scratch_server.py`).
- Office tokens (`src/lib/office/ds-auth.ts`): never sign anything new with the raw office JWT secret except what the Document Server itself verifies (the editor config, command-service requests); app-only tokens use an HMAC-derived key per kind (capabilities, proxy tickets). A DS token is recognised by its shape (`payload` + `exp` in the header form; `key` + `status` + `exp` in the callback body), so a browser-visible token can never stand in for it.
- In-memory maps keyed by a client-chosen id (UI bridge polls) only take ids that already have an owning record (presence) and are removed with it: never record an id the client merely names.
- Forwarded headers: Next keeps a client-sent `X-Forwarded-For` and route handlers never see the socket, so `scripts/serve.mjs` preloads `scripts/peer-address.mjs` (stamps the TCP peer into `x-knife-peer`, overwriting any client value) and `src/lib/accounts/network.ts` trusts `X-Forwarded-For`/`-Proto` only when that peer matches `KNIFE_TRUSTED_PROXIES`. A server started without `serve.mjs` never trusts them.
- Playwright: typing into a controlled input before hydration is lost (the input shows the text, React state stays empty, attributes mismatch in the console). Navigate with `wait_until="networkidle"` before filling forms (`tests/functional/accounts_public_e2e.py` `go()`).
- `scripts/serve.mjs` passes exactly ONE `--import` in `NODE_OPTIONS`: Next re-serialises NODE_OPTIONS for its child and mangles a second quoted `--import` into one path. `peer-address.mjs` chains `security-headers.mjs` when `KNIFE_SECURITY_HEADERS_INSTALL=1`, then `office-proxy.mjs` (requests for `KNIFE_OFFICE_PUBLIC_URL`'s host go to the office sidecar and never reach Next or get the app's headers), then `abuse-guard.mjs` (outermost: refused requests never reach the office proxy, the headers or Next; it also sets the Node server timeouts and `maxConnections`). The guard and the office proxy run in the preload, so they are plain `.mjs` sharing `src/lib/net/client-ip.mjs` and `src/lib/security/events-core.mjs` with the app; never import TS from them. Security headers are set at runtime by that preload, not in `next.config` `headers()` (frozen into the build, while the office editor's origin is runtime state); a server started without `serve.mjs` sends none.
- ArtCraft apps (`craft` sidecar): they must stay on their own origin like the office editor (never a path on the app's origin, which would hand app bugs the signed-in user's session), and the iframe sandbox carries `allow-scripts allow-same-origin`, which is safe only because the frame is cross-origin. Over plain-http Tailscale they are not in a secure context: no WebGPU (WebGL2 fallback), no OPFS (IndexedDB), no async clipboard. The app CSP lists the craft origin in `frame-src` only. Headless Firefox has no WebGL2: `tests/craft_e2e.py` runs headed under `xvfb-run`. The generated nginx.conf names no app version: releases live in `services/craft/releases/`, the active one per app is hard-linked into the content dir `services/craft-content/` (a sibling, mounted read-only), so an update or a pin bump only relinks that dir (no compose change, no recreate, and with the root helper no `sync`: root copies the content through its `content` verb). Keep it that way: anything version-dependent in compose or nginx.conf would bring back the manual sync per update.
- CSP office origin (`scripts/security-headers.mjs` `officeOrigins`): public mode trusts only `KNIFE_OFFICE_PUBLIC_URL` when it is https on a public host name (never the sidecar state file, never plain http, a private/CGNAT/loopback address or a `.local`/`.ts.net` name) and otherwise leaves the editor out of the CSP with a startup warning; `KNIFE_CSP_FRAME_ORIGINS` gets the same filter in public mode. Private mode keeps the state-file fallback (`publicUrl`, else bind:port).
- Load budgets: a new route that streams a body to disk takes an `upload-budget.ts` slot before reading and passes `reservation.bytes` + `uploadIdleTimeoutMs()` to `receiveMultipart`; new Python work goes through `runPythonScript`/`startPythonScript` (admission is applied there) and a route that receives an upload first calls `assertPythonCapacity` before reading it. `canStore` answers for the quota only (the office save drops old versions to make room; low disk must not delete history), `assertCanStore` also applies the disk floor.
- Sidecar definitions must state `security.capAdd` (compose renders `cap_drop: [ALL]`, `no-new-privileges`, `pids_limit`): verify a new image or an image bump with every other capability dropped (start, health, its `prepare`, stop, restart: `tests/learn_db_e2e.py`, `tests/office_e2e.py` with `KNIFE_E2E_SIDECAR_PREFIX`) before changing the set.
- `npm run start` serves the last `npm run build` (serve.mjs refuses without `.next/BUILD_ID`); it is the public deployment shape (docs/DEPLOY.md). CSP needs `'unsafe-inline'` (Next bootstrap, theme script; static pages, no nonces), `'unsafe-eval'` (ajv in the JSON Schema tool) and `'wasm-unsafe-eval'` (sql.js, tesseract): script-src is not the XSS barrier, frame-ancestors/connect-src/object-src/base-uri/form-action are what it adds.
- Euro-Office Document Server request filter: URLs inside the JWT-signed config and command requests (document download, save callback) are trusted and NOT filtered; only URLs a user types into the editor are. So `ALLOW_PRIVATE_IP_ADDRESS=false` with an empty allow list works, and adding the app's IP to `allowIPAddressList` would open every port on that IP (the list is per address). Verified with `AddImageUrl` in the editor frame (docs/SIDECARS.md "Request filter").
- Storage quota (`src/lib/storage/quota.ts`): usage is counted once per account and then moved by exact deltas, so a file written or removed behind the server's back (a test filler, a hand edit, the CLI) is only seen after `KNIFE_STORAGE_RECOUNT_SEC` (default 600; e2e suites set 1). Stores must not import `src/lib/accounts/authz.ts` (it loads `next/server`, which `node --test` cannot resolve): the quota restates the admin rule from `mode.ts` instead.
- Office library: `DELETE /api/office/docs/<id>` moves to the trash (restorable for 30 days, still counted by the quota); `?permanent=1` deletes for good. Trashing a folder trashes its subtree with `trashedWith = <folder id>`, and only that folder can be restored or deleted forever (its contents answer 409). Restoring a version rotates the key, so an editor session open on the old key saves its next change as "<name> (edited copy)".

- Rate limits (`src/lib/accounts/rate-limit.ts`): every limit is a `LIMITS` entry (per-address ones through `addressLimit`, so they get the /48 companion); a new namespace (the key's first segment) gets a policy in `NAMESPACES` (pre-login = never evicts, refuses heavy creators past its cap; signed-in = evicts least recently used non-limiting). Signal buckets (`quiet`) only raise proof-of-work; never turn one into a refusal. Known-device logins pass `{ trusted: true }`.
- Isolate pool workers are `unref`'d while idle and `ref`'d while they run a task (`pool.ts`): attaching a `message` listener re-refs a `worker_threads` Worker, so unref only after the listeners, or a unit test or CLI that used the pool never exits. Unit tests (`tests/isolate_server.test.mjs`) start the REAL worker: it inherits `--import ./tests/ts-resolve.mjs` through `execArgv`.
- Public account abuse controls live in `src/lib/accounts/pow.ts`, `hash-gate.ts`, and `pending.ts`: run the signed, one-use proof-of-work gate before any hash/store/mail work; all scrypt calls share a bounded async gate; never add unbounded per-request state. See `docs/ACCOUNTS.md`.
- External return URLs must use `src/lib/safe-return.ts` on both server and browser; never trust a raw OAuth `returnTo`/`next` value. OAuth state must remain one-time and browser-bound; see `docs/GITHUB.md`.
