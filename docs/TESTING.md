# Testing

All e2e suites are Python 3 + Playwright (chromium) against a running server. Default to the scripted mock provider (`node tests/mock_provider.mjs 3299`, requires `Authorization: Bearer mock-key`). Never point a suite at a shared or production model server.

Suites that create accounts or provider settings need an isolated data dir and their own port so they never touch the live instance (`:3210`, PM2) or its data. The AI coverage runner starts and cleans up its own isolated scratch server when no URL is supplied:

```bash
KNIFE_REAL_ACCOUNT=openclaw python3 tests/agent_coverage_e2e.py [--group docs|media|data|css_time|web|db|cv] [--only slug[:tab] ...] [--concurrency 1]
```

On a shared host, `KNIFE_SCRATCH_PORTS=3330-3349` makes every self-contained suite (`tests/scratch_server.py`) take its port from that range, and `KNIFE_E2E_SIDECAR_PREFIX=<name>` gives the docker suites (`office_e2e.py`, `learn_db_e2e.py`) a fixed compose project name; `TMPDIR` decides where the scratch worktree and data dir go. `KNIFE_SECURITY_HEADERS=1` runs a private-mode scratch server with the public-mode headers (the office e2e then proves the editor loads and saves under the CSP).

Pass an existing scratch URL as the first argument to reuse a server. The default run uses a temporary data directory and an available loopback port, and stops the server on exit; it never starts, reads, or mutates the live `:3210` service or data.

## Unit tests (no server, no browser)

`npm run test:unit` runs every `tests/*.test.mjs` (Node >= 24: native type stripping; `tests/ts-resolve.mjs` also resolves extensionless relative imports and the `@/` alias so server modules such as `src/lib/cv/store.ts` can be imported). One file: 

```bash
R="node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --disable-warning=ExperimentalWarning --import ./tests/ts-resolve.mjs --test"
$R tests/csv_tools.test.mjs      # CSV convert keys (duplicate/extra/blank headers, BOM), pivot ignores blank cells, markdown table with header off
$R tests/yaml_json.test.mjs      # YAML/JSON: big integers stay exact (+ warning), .inf/.nan warn, parity with JSON.parse
$R tests/sql_instant_format.test.mjs   # instant formatter: formatted SQL returns the same rows as the original in SQLite (node:sqlite), -- comments never swallow code
$R tests/cv_store.test.mjs       # damaged cv/<id>.json is a CvStoreError, undo snapshots never share a name, ids with path characters refused
$R tests/accounts_store.test.mjs  # accounts v1->v2 migration, lock, unique emails, trusted-proxy rules, rate limits, public flows, data purge
$R tests/nosql.test.mjs tests/work-queue.test.mjs tests/workers.test.mjs tests/sql_runtime.test.mjs tests/wait_condition.test.mjs tests/tool_groups.test.mjs tests/agent_runtime_store.test.mjs tests/cv_*.test.mjs tests/random-uuid.test.mjs tests/sql_engine.test.mjs tests/accounts_cli.test.mjs
```

Per-file notes (older suites): `sql_engine` loads src/lib/sql/types.ts natively and checks the zod contract against the Python engine's dialect list and placeholder table; `nosql` = NoSQL lab compilers; `work-queue` = queue ordering, lane caps, light/heavy isolation, depth limit, abort queued/running (real process groups), timeout, stats, runPythonScript on a fake interpreter; `workers`/`sql_runtime` = worker pool (FIFO, bounded concurrency, abort, timeout, crash recovery, transferables, lazy spawn) and the SQLite runtime; `wait_condition` = wait_for condition logic; `tool_groups` = on-demand tool groups (page preload, conversation memory, load_tools, stable prefix order); `agent_runtime_store` = the 8x8 run-state transition table against a written-out oracle, illegal moves reported and ignored, Stop while parked, recovery from a run that never ended.

SQL engine notes: no suite touches a database server. The engine needs `sqlglot` in the Python venv (`../samurai-knife-py/venv/bin/pip install -r server/py/requirements.txt`). Placeholder styles produced by `compile`: `?` sqlite, mysql, mariadb, duckdb, snowflake, clickhouse, trino, spark, hive (one `params` entry per placeholder); `$1` postgres, redshift; `@name` tsql, bigquery; `:name` oracle (named/numbered styles list each name once). ## Real model via the OpenClaw gateway

The local gateway serves an OpenAI-compatible endpoint (`gateway.http.endpoints.chatCompletions.enabled`, OpenClaw doc `docs/gateway/openai-http-api.md`): `http://127.0.0.1:18789/v1` (`/models`, `/chat/completions`, streaming, `stream_options.include_usage`, client function `tools`). It is an OpenClaw AGENT, not a raw provider: `model` is an agent target (`openclaw/<agentId>`), every request is a full agent run (the agent's own system prompt and tools apply) and a valid token is a full operator credential. Use it as a test provider only through a restricted agent (`main` has exec/elevated tools; the CLI and the harness refuse it without `--allow-main` / `KNIFE_GATEWAY_ALLOW_MAIN=1`).

One-time setup, in an INTERACTIVE terminal (the token cannot be piped or redirected out of `openclaw gateway auth-token --show` by design; tokenless Tailscale auth covers the Control UI only, the HTTP API answers 401):

```bash
cd ~/work/Samurai-Knife
npm run accounts -- add openclaw --name "OpenClaw gateway" --password-prompt      # a Knife account is the profile
openclaw gateway auth-token --show                                                # copy the token
npm run accounts -- set-provider openclaw --preset openclaw-gateway --agent openclaw/<restricted agent> --key-prompt   # paste it (hidden)
npm run accounts -- list                                                          # shows only a key hint
```

Optional `--backend-model provider/model` sends `x-openclaw-model`; `--gateway-url` overrides the URL. Then:

- `KNIFE_REAL_ACCOUNT=openclaw python3 tests/gateway_probe.py` first (models, plain, streaming + usage, client-tool round trip, isolation check that the agent cannot run a shell).
- `KNIFE_REAL_ACCOUNT=openclaw python3 tests/agent_chain_real_e2e.py <scratch-url>` (and the other `*_real_e2e.py`): the harness reads that account's provider READ-ONLY from the live `accounts.json` and pushes it to the scratch server's throwaway data dir. `KNIFE_REAL_ACCOUNT` works for any provider profile, not only the gateway.
- Without an account: `KNIFE_REAL_PROVIDER=openclaw-gateway KNIFE_GATEWAY_AGENT=openclaw/<agent>` with the token in `OPENCLAW_GATEWAY_TOKEN` or the 0600 file `~/.openclaw/secrets/gateway-api-token`.

### The working recipe (2026-10-09, gateway 2026.9.8) and what was learned

Default Claude models run in the `claude-cli` runtime, which brings Claude Code's native Bash/Read/Write/WebFetch and hides HTTP client tools behind native `ToolSearch`: isolating it (`exec` denied) also blocks client tools, so it cannot drive Knife's widget loop. An OpenAI model on OpenClaw's own embedded runtime does both safely. The restricted agent that works (`agents.entries.knife-test` in `~/.openclaw/openclaw.json`; it hot-applies, check `journalctl --user -u openclaw-gateway | grep reload`, an invalid edit is SKIPPED silently):

```json5
"knife-test": {
  workspace: "~/.openclaw/workspace-knife-test",        // OpenClaw seeds it with first-run files: contextInjection "never" ignores them
  model: "openai/gpt-6-luna",                          // ChatGPT login (shared OAuth), no key copy needed
  models: { "openai/gpt-6-luna": { agentRuntime: { id: "openclaw" } } },   // force OpenClaw's runtime, not Codex's
  contextInjection: "never",                           // no persona/bootstrap text in replies, ~3.9k prompt tokens instead of ~8.9k
  tools: { allow: ["session_status"], deny: [ /* exec read write edit web_fetch ... */ "*" ], exec: { mode: "deny" }, fs: { workspaceOnly: true } }
}
```

Notes: `exec.mode` cannot be combined with `security`/`ask`; the model's only tool is Code Mode's JavaScript `exec` (no modules, no `process`/`os`/`fetch`: verified by deliberate escape attempts); HTTP client tools arrive through OpenClaw's structured tool search. Per-call latency ~3-8 s. `gateway_probe.py` (isolation + client tool round trip) takes ~30 s.

Results through this provider (`KNIFE_REAL_ACCOUNT=openclaw`, scratch server): `agent_chain_real_e2e` pass; `agent_sql_real_e2e` pass (10 cases; oracle fixed to accept dialect-named fences such as ```postgresql); `agent_ocr_chain_real_e2e` pass 1/1 after the prompt made the Download click explicit ("not finished until YOU clicked it": the model had compressed the file and told the user to click); `cv_agent_real_e2e` pass (applications from a non-CV page, applied-on date, open list, honesty trap: "15 years" is flagged against the profile's dates, not written; offer gap not added). `agent_wait_real_e2e` 1/2: with "profile a CSV I will give you" the model picked the Table inspector (paste-only, no file input) and honestly said so; that is tool choice variance, not a bug.
