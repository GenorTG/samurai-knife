# Interface languages (English, Polish)

The whole app speaks English and Polish: shell, every tool and suite tab, the assistant widget, account pages, server
messages, account emails and the SQL & PostGIS course. One global choice per reader; no URL prefix (tool slugs are
permanent, so `/tools/<slug>` stays the same in both languages).

## Choosing the language

- **Top bar**: `LanguageSwitcher` (`src/components/LanguageSwitcher.tsx`) shows the current code (`EN` / `PL`) and flips
  to the other one. **Account settings** has the same choice as a radio group (`LanguageChoice`).
- A switch calls `POST /api/locale {locale}` (Origin/Host guard, JSON only): it sets the `knife_lang` cookie (one year,
  `SameSite=Lax`, `Secure` on https) and, when someone is signed in, saves `language` on the account
  (`setAccountLanguage`, `src/lib/accounts/store.ts`). The page then re-renders through `router.refresh()`.
- Resolution on every request (`getLocale()`, `src/lib/i18n/server.ts`): cookie, then the account's `language`
  (signed in, or the default account in private mode), then `Accept-Language`, then English. Route handlers use
  `requestLocale(request)` (cookie, then `Accept-Language`).
- A new account records the language of the sign-up page, so its emails are in that language from the first one.

## How texts are translated

- **English is the key.** `src/lib/i18n/pl.json` maps each English text to its Polish translation; a plural is
  `[one, few, many]` (Polish `Intl.PluralRules`: 1 plik, 2–4 pliki, 5+ / 12–14 / 22 plików… `other` uses `few`).
  Placeholders are `{name}` and must be the same on both sides.
- **Components**: `const { t, tn, m, num, date, locale } = useT();` (`src/lib/i18n/react.tsx`):
  `t("Save offer")`, `t("Opened {name}.", { name })`, `tn("{n} file", "{n} files", count)` (`n` is filled in).
- **Server components / pages**: `const { t } = await getT();` and `generateMetadata` instead of a static `metadata`.
- **Module-level texts** (registry names and taglines, option lists, workflow node catalog, lesson check messages):
  mark them with `msg("…")` (an identity function the extractor reads) and translate where they are rendered: `t(x)`.
  Shared primitives already do it for string props: `Field` label, `Stat` label, `Notice` text children,
  `KeyValues` keys, `CopyButton` / `FullscreenButton` labels.
- **Server messages with values** (`jsonError`, thrown errors, account flow messages): `msgf("Unknown lesson {id}…",
  { id })` returns the English text; the browser translates it back by template (`m(message)` from `useT`, `cmsg` in
  plain helpers such as `src/components/account/api.ts`): `translateMessage` matches the catalogue templates.
- **Browser-runtime code outside React** (approval cards, step labels, tool summaries): `ct` / `ctn` / `cmsg`
  (`src/lib/i18n/client-locale.ts`, set by the provider).
- **Never** translate: tool slugs, ids, code, SQL, regexes, file formats, product names, MCP tool output meant for agents
  (the deterministic `knife_*` results stay English), model-facing hints of the assistant tools.
- The assistant is told to answer in the interface language (`system-prompt.ts`, `locale` from `clientLocale()`).
- Workflow files the worker imports cannot use `@/` imports (Node type stripping): their catalog labels are collected
  by the extractor from known keys (label, description, hint, placeholder…), not from `msg()`.

## Content with its own Polish edition

- **SQL & PostGIS course**: `src/lib/learn/sql/lessons.ts` is the source (ids, starters, solutions, checks);
  `src/lib/learn/sql/lessons.pl.json` overlays title, explanation, task and hints per lesson id, plus module titles and
  summaries (`localizeCourse`, `src/lib/learn/localize.ts`). SQL in code blocks and hints stays identical. Check
  feedback (`compare.ts`, `check.ts`) takes a translator; `POST /api/learn/sql/check` passes the request's language.
- **Account emails** (`src/lib/mail/templates.ts`): every template takes `locale` (account `language`, or the language
  of the sign-up / reset page for address-only mails).
- **Legal pages**: Polish is the binding edition, English a translation (`docs/LEGAL.md`); `/terms` and `/privacy`
  open in the interface language unless `?lang=` asks for one.
- The Markdown tool's starter document has a Polish version; other sample data (CSV, JSON, SQL samples) stays as is.

## Fonts

Geist ships its Latin glyphs in the main files and Polish letters (ą ć ę ł ń ó ś ź ż) in a separate latin-ext file:
`src/app/layout.tsx` loads both (`--font-geist-sans-ext`, `--font-geist-mono-ext`, no preload) and `globals.css` lists
the ext family second, so Polish letters never fall back to Arial. `adjustFontFallback: false` on the main fonts keeps
the browser from picking the metric-adjusted fallback before the ext face.

## Adding or changing text

1. Write the English text through `t` / `tn` / `msg` / `msgf` (a full sentence per key: never split a sentence around
   a value or a link; never build plurals with `"s"`).
2. `node scripts/i18n-extract.mjs --write` adds the new keys (empty) and drops stale ones; translate them in
   `src/lib/i18n/pl.json` (informal *ty*, imperative buttons, Polish quotes „…”; tool = narzędzie, tab = karta,
   suite = pakiet, workflow = przepływ pracy, node = węzeł, sidecar = usługa dodatkowa).
3. `node scripts/i18n-extract.mjs` must report `missing 0, stale 0, mismatched 0, dynamic 0`; `tests/i18n.test.mjs`
   fails otherwise.

## Tests

- `tests/i18n.test.mjs`: catalogue complete and in step with the code, plural forms, template translation of server
  messages, locale negotiation, the Polish course overlay (same lessons, same SQL, same checks) and Polish check feedback.
- `tests/functional/i18n_e2e.py`: the switch in a real browser (cookie, account, reload, Accept-Language), Polish
  pages hydrating without mismatches, the latin-ext font face loaded, the account-page choice, `POST /api/locale`
  refusing other languages.
- `python3 tests/visual_diff.py audit <url> --lang pl`: layout offenders with the longer Polish strings (compare with
  `--lang en`). Playwright suites run with `en-US`, so the other suites stay in English.
